# docker anonymous volume keeps stale node_modules

Date: 2026-06-15 23:06

---

A compose service that bind-mounts source and excludes `node_modules` with an anonymous volume can keep stale dependencies:

```yaml
volumes:
  - ./frontend:/app
  - /app/node_modules
```

The bind mount hides the image's `/app/node_modules`, and the anonymous volume persists whatever was installed on the first run. After changing frameworks or lockfiles, `docker compose up --build` still starts with the old volume, producing errors such as a missing `@vitejs/plugin-vue`.

Remove the anonymous volume before rebuilding:

```bash
docker compose down -v
docker compose up --build
```

`down -v` deletes anonymous volumes, so use it deliberately. For a more predictable setup, use a named volume or install dependencies on the host and keep them in the bind mount. Verify with:

```bash
docker compose exec frontend ls /app/node_modules/@vitejs
```
